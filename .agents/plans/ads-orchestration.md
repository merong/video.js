# 광고 제품 Herdr 실행 조직

기준일: 2026-10-18. 제품 범위는 `ads-module-plan.md`의 D01–D12다. 이 문서는 임시 작업 계획이며 병합 전에 정리한다. 최신 실행 상태와 실제 에이전트 ID는 `ads-orchestration.json`, 검증 증거는 `ads-validation.md`에 기록한다.

## 구성

Herdr `tools` 세션의 `video.js` 워크스페이스(`w1`)가 실행 위치이며 현재 대화(`w1:p1`)가 오케스트레이터다. 제품 개발 작업자 5명은 동일 checkout의 Codex `gpt-6-astra`, reasoning `xhigh`다. 예제 영상 담당 `grok`는 Grok CLI로 실행하며 Grok Imagine의 제작 요청을 받는다. 모든 탭은 최대 2개 pane으로 유지한다: 오케스트레이터·Grok `w1:t1` 2개, 플레이어·리뷰 `w1:t2` 2개, 관리자 API·UI `w1:t3` 2개, 독립 QA `w1:t4` 1개.

2026-10-18 세션 대상 오류를 수정했다. 이전 `default / blender`의 광고 작업자 5개 프로세스를 정상 종료하고 기존 Codex 대화 ID를 `codex resume`으로 이어서 실행했다. `HERDR_*` 환경변수가 이전 위치를 가리킬 수 있으므로 모든 제어 명령에 `herdr --session tools`를 명시하고 위의 실측 ID를 사용한다. 세션명이 없는 pane ID는 다른 서버에서 재사용될 수 있다.

5명 모두 새 위치에서 `MIGRATION READY` 응답을 반환했다. 기존 광고 전용 탭 `default:wB:t6`, `default:wB:t7`, `default:wB:t8`은 정상 종료된 셸만 있는지 확인한 뒤 닫았으며, 기존 Blender 작업 탭 5개와 현재 오케스트레이터는 유지했다.

## 파일 소유권

아래는 실제 구현 소유권이다. 각 작업의 착수 지시에서 허용한 경로만 수정한다. 완료된 1차 작업 W0는 읽기 전용 분석이었다.

- 오케스트레이터: `.agents/plans/ads-*`, 공통 계약·교차 플랫폼 fixture, 루트 manifest/lockfile/TS 참조·빌드 설정, 공용 core/html 연결부. 계약과 공통 fixture의 단일 작성자이며 필요 시 명시적으로 소유권을 넘긴다. 공통 파일은 한 번에 한 담당자만 수정한다.
- 플레이어: `packages/extensions/ads/**`. `apps/sandbox/templates`와 CDN/E2E 공용 파일은 별도 배정 후 수정한다.
- 관리자 API: `integrations/ads-manager/` 아래의 `src/**`, `database/**`, `public/api/**`, `hosts/**`, `tests/backend/**`, 설치/실행 설정. C0에서 확정한 PHP/PDO·MySQL 관리자 서버를 Video.js 런타임 패키지와 분리한다. SQLite는 빠른 로컬 검사에도 사용한다.
- 관리자 화면: `integrations/ads-manager/` 아래의 `admin/**`, `public/assets/admin/**`, `tests/admin/**`. API 소유의 host bootstrap·DB·인증을 복제하지 않고 합의한 연결 함수를 사용한다.
- 분석/QA: 기본 읽기 전용. 테스트 자산 작성이 필요하면 별도 파일 범위를 배정한다. 코드를 직접 고치거나 실패 기준을 낮추지 않는다.
- Grok: `workspaces/ads-media/**`의 예제 영상 요청·프롬프트·원본/파생물·manifest. 초기 인수 후 Grok Imagine의 구체적 제작 요청을 기다린다. 제품 코드·기존 예제 파일·서버 설정은 변경하지 않는다.

`../v10`와 외부 그누보드 가이드는 읽기 전용 참조다. 외부 고객 DB·운영 서비스·다른 프로젝트는 작업 대상이 아니다. 모든 담당자는 다른 작업자가 있음을 전제로 변경을 보존하며 전체 reset/restore·타인 수정 덮어쓰기를 하지 않는다.

## 확정 제품 계약

- 독립 설치와 그누보드·영카트 연결, 자체 JSON, HTML 스크립트, VOD 우선.
- MP4/WebM·이미지·GIF 소재를 URL 또는 업로드로 등록.
- 프리롤 단일/여러 개, 미드롤, 포스트롤. 각 광고는 스킵 불가 또는 N초 후 가능. 스킵은 현재 광고만 넘긴다.
- 탐색으로 건너뛴 미시청 미드롤은 한 구간만 실행하며 이미 본 구간은 반복하지 않는다.
- 사이트 기본 → 게시판·분류 → 개별 영상 순으로 예외 편성.
- 시작·완료·스킵·클릭·오류, 완료율·클릭률, 기간/광고/영상/게시판 필터, CSV 다운로드.
- 라이브·React·VAST/IMA·과금/정산·중앙 SaaS·광고 경매·방문 간 빈도 제어는 이번 작업에 넣지 않는다.

P1/A1/U1은 C0 후 병행한다. C0 통과는 오케스트레이터의 내부 리뷰 단계이며 사용자에게 같은 범위의 승인을 다시 요청하는 단계가 아니다. 미정인 기술값은 W0 권고를 검토해 기본값으로 기록하고, 새로운 제품 기능을 추가하는 결정과 구분한다.

C0는 형식 버전과 게시 버전의 구분, JSON·HTML 연결/해제·호환 범위, 상속/전체 대체/비활성 우선순위, 탐색/스킵/실패/재시청 기대값, 이벤트 식별·통계 분모·기간/시간대·CSV 열, 관리자 DTO·권한/검증 오류, 서버 기술·검증 환경을 명시해야 통과한다. C0 미통과 상태에서 구현 담당자가 이 값을 각자 확정하지 않는다.

## 실행 규칙

1. 매 작업은 작업 ID·허용 파일·금지 경로·의존성·검증·완료 보고 형식을 포함해 Herdr `agent prompt`로 배정한다. 자동으로 다음 단계나 다른 에이전트를 시작하지 않는다.
2. `agent get`의 cwd/세션/상태와 실제 응답을 대조한다. `done`은 응답 완료이며 제품 완료가 아니다. 제출 뒤 `working` 또는 신규 응답을 확인한다.
3. 에이전트는 변경 파일, 실제 명령/결과, 미검증 항목, 선행 계약 충돌을 보고한다. 오케스트레이터가 diff와 대표 동작을 직접 확인한 뒤 작업을 통과시킨다.
4. 공통 계약을 바꾸려면 영향받는 담당자에게 먼저 알리고 오케스트레이터가 계약을 한 번 수정한다. 각자가 같은 JSON/API를 다르게 정의하지 않는다.
5. 루트 설치·lockfile·전체 빌드는 오케스트레이터가 직렬화한다. 작업자는 좁은 범위 검사만 실행하고 기존 개발 서버를 재시작하거나 다른 포트를 점유하지 않는다.
6. Node 작업은 저장소 루트에서 pnpm만 사용한다. 이 세션에서 확인한 실행 경로는 `mise exec node@24.14.0 -- corepack pnpm@12.6.0 <command>`다. PHP/DB 도구는 W0에서 존재를 확인하고 설치·지원 버전을 추정하지 않는다.
7. 출력 타입을 변경하면 관련 패키지 빌드 후 타입 검사한다. 의미 있는 동작 테스트, 코드 리뷰, 실제 브라우저 확인을 구분하며 fixture 통과를 실제 DB/서버 통합 완료로 쓰지 않는다.
8. 커밋·push·배포·실제 고객 데이터 이전은 현재 작업에 포함하지 않는다. 비활성화/삭제는 데이터 보존 정책을 정한 뒤 별도 구현한다.

## 현재 착수 범위

W0와 C0 뒤 P1/P2, A1/A2, U1/U2를 구현하고 실제 MySQL·독립 설치·그누보드 환경에서 I1/Q1을 검증했다. R1 지적과 실제 재생 결함을 수정한 뒤 소스 재리뷰와 브라우저 회귀를 통과했다. H1은 검증한 로컬 범위로 인계했으며 다른 브라우저·운영 배포까지 승인한 것은 아니다. QA의 원본 실패와 통과 증거는 `/tmp/ads-qa-txrhuzog`, 요약은 `ads-validation.md`에 보존한다. 다섯 작업자는 작업을 마치고 후속 배정 대기 상태다.

W0 당시 직접 대조한 근거(현재 구현 상태는 위 실행 상태와 검증 기록 참고):

- `packages/core/src/dom/extensions/extension.ts`: 현재 확장 계약은 `@internal`이고 컨테이너만 바뀌면 attach하지 않는 수명 계약이 있다. 외부 안정 API로 임의 승격하지 않는다.

- 상태 파일의 에이전트 이름/pane 중복 없음, 16개 작업 ID·의존 대상 유효성 및 순환 없음은 JSON 검증으로 확인했다. 작업 상태는 관측 시점의 기록이며 백그라운드 자동 스케줄러가 아니다.
- 변경 파일은 광고 계획/오케스트레이션 문서·상태 파일뿐이다. 플레이어·관리자 제품 코드와 DB는 아직 변경하지 않았다.

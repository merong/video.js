## 현재 소스에서 직접 확인한 사실

- 참조 구현은 `packages/ads/`의 `<media-ads>` 사용자 정의 요소다. HTML 플레이어의 컨텍스트를 소비하며 JSON 광고 목록을 요청한다.
- 광고는 별도 `<video>` 또는 `<img>` 오버레이로 표시하며, 현재 선택 코드는 목록의 첫 광고만 사용한다.
- `skipAfter > 0`인 경우에만 스킵을 허용한다. `0`은 즉시 스킵을 의미하지 않는다.
- 실제 트래커는 `{ event, ...extra }`를 전송하지만 현재 요소의 호출은 `adId`나 시청 시간을 넘기지 않는다. README의 페이로드 설명과 차이가 있다.
- 현재 프로젝트에는 `PlayerExtension`과 미디어 override, 수명 관리 조정자가 있다. 해당 계약은 `@internal`이므로 외부 배포 API로 그대로 노출하는 결정과 내부 연동은 구분해야 한다.
- 기존 저장소는 tsdown/Vitest 4 기반이고 현재 저장소는 Vite+/Vitest 5 기반이다. 빌드 설정을 그대로 복사하는 방식은 적용하지 않는다.

### 기술 제안에 대한 리뷰 결정

- **채택한 방향:** 독립적으로 선택하는 광고 모듈, 플랫폼 중립 상태·정책과 DOM 연결의 분리, 종료 결과 구분, 비동기 취소와 소유권 명시, 작은 작업별 검증.
- **우선 후보:** `packages/extensions/ads`에 모듈을 배치한다. `packages/ads`도 workspace에 이미 포함되므로 기술적으로 가능하다. 최종 경로는 배포·호환 요구를 확인한 뒤 정한다.
- **자동 채택하지 않음:** 여러 공급자를 위한 범용 provider 시스템, 다수의 public entry point, React/CDN/IIFE 동시 지원. 첫 출시 요구에 필요한 경계만 구현하며 미확정 기능을 위한 추상화를 먼저 만들지 않는다.
- **공개 계약 주의:** 현재 PlayerExtension·등록 helper는 내부 계약이다. 비공개 파일 deep import를 하지 않고, 저장소 내부 바인딩과 외부 안정 API를 구분한다. 외부 배포 시 지원 버전 범위를 명시한다.
- **공통 파일 변경 예상:** 새 TS 프로젝트 참조와 의존성 lockfile이 기본 후보다. workspace glob·빌드 helper·CI 탐색은 재사용 가능하다. 공용 HTML/React/CDN facade, 배포 설정, 확장 우선권 변경은 요구가 생긴 경우 별도 작업으로 배정한다.
- **구 코드 재사용 범위:** 데이터 스키마·로더·트래커·오버레이 DOM/CSS를 참고하되 검증과 이벤트 의미·접근성을 보완한다. 기존 MediaAdsElement의 재생/취소/복귀 로직을 그대로 이식하는 안은 채택하지 않는다.

| FR-08 | 로그 | 시작·완료·스킵·클릭·오류, 완료율·클릭률을 제공한다. 기간/광고/영상/게시판 필터와 CSV 다운로드를 지원한다. 지표의 분모와 보존·중복 처리 정책은 계약에서 정의한다. |
| FR-09 | 호스트 연동 | 고객별 독립 설치와 그누보드·영카트 관리자 연동을 제공한다. 공통 광고 데이터/플레이어 계약과 호스트별 관리자 접근·저장 연동을 구분한다. |
| FR-10 | 탐색 | 탐색으로 건너뛴 미시청 미드롤은 탐색 직후 한 구간만 실행하고 이미 본 구간은 반복하지 않는다. |
| FR-11 | 적용 계층 | 사이트 기본 편성에 게시판·분류별 편성과 개별 영상 예외를 적용한다. |

### 플레이어와 관리자 모듈의 책임 분리 초안

사용자는 별도 관리자 모듈 구현까지 범위에 포함했다. 고객별 설치와 그누보드·영카트 연결은 확정됐으며 아래 상세 책임과 서버 기술은 설계 검토 중이다.

- 플레이어 광고 플러그인: 설정/JSON 수신, 광고 표시·재생·스킵, 본편 제어와 복귀, 정의된 광고 이벤트 발생, 연결 해제 정리.
- 광고 노출 관리자 모듈: 광고 소재·편성·노출 설정을 저장하고 서비스에 맞는 광고 응답과 통계를 제공한다. 캠페인·선택·빈도·집계의 구체적 기능 수준은 후속 인터뷰에서 결정.
- 연동 규격: 광고 요청의 서비스·지면·콘텐츠 식별, JSON 응답 형식과 버전, 이벤트 의미와 식별자, 오류/시간 제한, 교차 출처 사용 조건을 정의할 필요가 있음.
- 관리자 UI와 영속 데이터·로그 저장 구조는 범위에 포함한다. 중앙 다중 고객 호스팅·결제·정산·광고주 포털은 포함하지 않는다. 독립 설치본의 관리자 접근과 그누보드 기존 관리자 권한 연동을 별도로 정의한다.

2차 에이전트 작업에서는 관리자/플레이어 경계와 MP4/HLS VOD 경로, HTML 스크립트 배포와 패키지 의존·등록 문제를 읽기 전용으로 검토했다.

### 2차 분석 리뷰: 자체 광고 관리자와 연동

분석 담당의 후속 보고를 검토하여 아래를 기술 권고로 반영했다. 아직 사용자 미답변 정책을 확정하는 내용은 아니다.

- 캠페인·우선순위·광고 선택·방문 간 노출 빈도 판단은 별도 관리자/서버에서 수행하고, 플레이어는 이번 재생에 제공된 광고를 실행하는 구조를 우선한다. 정적 JSON은 간단한 구성으로 허용할 수 있으나 서버에서 집계한 빈도 제한과 같은 보장 수준으로 취급하지 않는다.
- 플레이어는 실제 관측한 광고 이벤트와 식별자를 제공하고, 관리자 측이 중복 제거·집계·보고를 담당하는 방향이다. 실제 수신·확정 노출·매출 처리는 브라우저 전송 성공과 구분한다.
- 관리자 UI 구현 자체와 플레이어 구현의 선행 조건을 구분한다. 요청 식별값, JSON 형식, 빈 응답, 이벤트 의미, 스킵/오류/재노출 계약이 정해지면 관리자 화면이 없어도 fixture 기반으로 플레이어를 구현·검증할 수 있다.
- 현재 MP4 본편은 일반 `<video>` 경로로, HLS 본편은 기존 custom media/adapter 경로로 연결한다. **HLS 본편 지원과 HLS 형식의 광고 소재 지원은 별도 요구사항**이다. 기존 광고의 `instanceof HTMLMediaElement` 제한을 그대로 유지하면 custom media를 지원하지 못한다.
- 배포 인터뷰에서 `type="module"` 허용 여부, classic script 단일 파일 필요 여부, 플레이어 포함/광고 추가 로딩 여부를 확인한다. 현재 공식 CDN은 ESM 공유 chunk 구조다.

### 2차 구현안 리뷰: HTML 스크립트 배포

구현 담당의 2차 후속 보고도 수신하여 아래와 같이 검토했다.

- `packages/extensions/ads`를 우선 후보로 유지한다. JSON·상태 제어·HTML 연결·표시 UI·등록·자체 테스트·데모·배포 설정을 해당 모듈에 모으고 React·다중 SDK용 시스템은 만들지 않는다.
- 기존 고객용 광고 추가 로딩 번들과 신규 설치용 플레이어 포함 번들을 구분한다. 통합 번들이 필수인지 선택인지는 아직 미정이다.
- 현재 플레이어 CDN은 ESM이다. 광고 코드만 IIFE로 만들어도 페이지 전체가 classic script만으로 구성되는 것은 아니다. classic script 전용 설치가 필요하면 플레이어 측 출력까지 작업 범위에 포함해야 한다.
- ESM/IIFE 단일 파일 출력은 빌드 설정상 후보이며 실제 빌드 성공·크기·브라우저 실행을 아직 검증하지 않았다. 일반 패키지의 unbundle 설정과 CDN 출력 설정을 분리해야 한다.
- 오케스트레이터가 `packages/html/src/i18n/index.ts`와 루트 export를 확인했다. HTML 루트 런타임 import에는 i18n 요소 등록 경로가 있으므로 광고 추가 번들에서 포함 범위·중복 등록을 확인한다. 작은 호환 연결부를 두는 제안은 검토 중이며 내부 컨텍스트 키를 복제하는 방식 자체를 확정하지 않았다.
- 처음에는 검증한 플레이어/광고 버전 조합을 명시한다. 같은 컨텍스트 Symbol 키를 쓰는 것과 값의 호환성, 이미 등록한 태그를 건너뛰는 것과 버전 충돌 해결은 별개다. 중복 스크립트 로딩도 인수 시나리오에 포함한다.

### 3차 분석 리뷰: 관리자 데이터와 광고 편성 실행

두 에이전트의 확장 범위 분석을 수신했고 Herdr `done` 상태를 확인했다. 오케스트레이터는 현재 `packages/core/src/dom/store/features/playback.ts`의 ended 동기화, `packages/media/src/core/types.ts`의 탐색·시간 계약, 기존 광고의 종료 후 무조건 play 호출과 타이머를 다시 대조했다. 아래는 구현을 위한 권고안이며 최종 API·DB 스키마는 아니다.

#### 최소 데이터 구조 제안

| 개념 | 책임과 주요 값 | 구현 경계 |
| --- | --- | --- |
| 사이트/지면/콘텐츠 식별 | 광고 편성 적용 대상과 데이터 소유 범위 | 설치형에서는 고객별 인스턴스가 경계가 될 수 있음. 중앙 다중 고객 DB를 전제하지 않음 |
| 소재와 버전 | 영상/이미지 종류, 파일 또는 URL, MIME, 대체텍스트, 확인한 영상 길이, 사용/보관 상태 | 파일 교체 후에도 과거 실행이 사용한 버전 식별 가능 |
| 광고 항목 | 소재 버전, 클릭 목적지, 스킵 방식/N초, 이미지 표시 시간 | 같은 소재를 다른 편성에 사용할 때 정책을 달리할 수 있는 구조 제안 |
| 편성 초안/게시 버전 | 적용 대상, 프리롤·미드롤·포스트롤, 미드롤 위치, 각 구간의 광고 순서 | 구간 안의 순서 있는 배열이 연속 광고 묶음. 구간·묶음을 각각 DB 테이블로 만들 필요는 없음 |
| 재생 세션 | 콘텐츠 재생 식별자, 적용 편성 버전, 실행할 구간 목록 | 사용자 로그인 세션과 구분. 서버 결정형/정적 JSON형 모두 계약 가능하도록 검토 |
| 광고 실행 시도 | 재생 세션, 구간/항목, 실행 ID, 상태·종료 사유 | 반복 노출과 재시도를 소재 ID 하나로 합치지 않음 |
| 관측 이벤트와 집계 | 이벤트 ID, 실행 참조, 발생/수신 시각, 순번, 콘텐츠/광고 시간, 결과 | 수신 원본과 통계 결과 분리. 물리 저장 방식은 설치 모델 결정 후 선택 |

- 게시한 편성은 버전을 부여한 JSON 스냅샷으로 제공하고 재생 중인 세션의 순서를 바꾸지 않는 안을 우선한다. 새 게시 버전은 새 재생 세션부터 적용하는 것을 제안한다. 긴급 중단은 별도 제품 결정이다.
- 소재 보관 처리와 파일 물리 삭제를 구분한다. 진행 중인 재생과 과거 통계 참조를 고려한 삭제 규칙을 설계한다. 보관 시 기존 게시 편성의 신규 실행을 어떻게 처리할지도 정한다.
- 정적 JSON 파일만으로 통계가 수집되지는 않는다. 각 고객의 설치 환경에 로그 수집·영속 저장 경로가 필요하다. 특정 서버 기술은 아직 선택하지 않았다.

#### 로그 생성과 통계 제안

- 플레이어는 구간 시작/종료, 광고 준비/실제 시작, 클릭, 광고 종료를 기록한다. 종료 사유는 완료·스킵·오류·시간 초과·취소를 구분한다. 요청/응답 및 서버 수신 사실과 실제 재생 시작을 같은 이벤트로 취급하지 않는다.
- 공통 식별값 후보는 `eventId`, `playbackSessionId`, `adAttemptId`, 편성/소재 버전, 구간/항목 ID다. 실행 내 순번, 클라이언트 발생 시각, 콘텐츠 위치와 광고 진행 시간도 포함한다. 수신 시각과 검증 결과는 수집 측에서 기록한다.
- 같은 이벤트 재전송은 같은 ID를 사용하고 한 번만 집계한다. 같은 ID에 다른 내용이 오면 충돌로 남긴다. 완료가 시작보다 먼저 수신되는 경우도 처리하고, 누락된 종료를 임의로 완료로 바꾸지 않는다.
- 통계 화면은 D12의 시작/완료/스킵/클릭/오류, 완료율·클릭률, 기간/광고/영상/게시판 필터와 CSV 다운로드를 제공한다. 분모·지연 로그·보존 정책은 공통 계약 작업에서 명시한다. 과금·정산 엔진은 범위에 포함하지 않는다.

#### 플레이어 실행 구조 제안

- **스케줄러:** 게시 스냅샷, 콘텐츠 시간 변화, 메타데이터와 실행 이력을 받아 실행할 광고 구간을 결정한다. 자연 재생과 seek를 구분하며 같은 구간이 중복 시작되지 않게 한다.
- **재생 제어기:** JSON 요청, 본편 제어권, 구간 내 광고 순차 실행, 취소·시간 제한·복귀를 관리한다. 편성 데이터와 실행 상태를 분리하며 범용 광고 공급자 시스템은 추가하지 않는다.
- 미드롤 위치는 본편 시간으로 계산한다. 영상 광고의 스킵·진행은 광고 재생 시간으로 계산하고 준비/정체 시간 제한은 별도 둔다. 이미지/GIF는 양수 표시 시간이 필요하며 GIF 반복 종료를 완료 신호로 가정하지 않는다. 숨긴 탭·일시정지 중 표시 시간 누적 정책은 미정이다.
- 스킵 버튼은 현재 광고만 종료하고 다음 광고로 진행한다. 다음 광고의 스킵 허용 시간은 새로 계산한다.
- 포스트롤은 본편 ended와 광고 종료를 분리한다. 포스트롤 완료 시 본편을 자동 재시작하는 기존 복귀 로직을 재사용하지 않는다. 다시보기/loop·광고 중 재생 요청의 동작은 후속 결정한다.
- 소스 변경·연결 해제 시 이전 요청·타이머·이벤트를 취소하고 이전 실행의 결과가 새 콘텐츠를 재생하지 못하게 한다. 동일 시각 구간, 범위 밖 미드롤, 늦은 메타데이터도 명시적 검증 대상으로 둔다.

#### 관리자 화면 흐름 제안

1. 소재 등록·미리보기·교체/보관.
2. 적용 대상 선택 → 시작 전/중간/종료 구간 추가 → 광고 순서 지정 → 항목별 스킵/표시 시간 설정.
3. 잘못된 위치·빈 구간·유효하지 않은 시간/소재 검증 → 실제 플레이어로 미리보기 → 저장·게시.
4. 통계 조회 및 필요 시 해당 실행 로그 확인.

사용자용 미리보기는 광고 편성을 확인하는 화면으로 구성한다. 개발용 시뮬레이터에서만 시계·실행 ID·오류 주입 같은 진단 정보를 노출한다. 시뮬레이터 통과와 브라우저의 실제 광고 재생 검증은 별도다.

### 4차 분석 리뷰: 설치형 관리자와 탐색 규칙

두 에이전트의 후속 보고를 수신했고 Herdr `done` 상태를 확인했다. 그누보드 연동 제안은 로컬 가이드·스키마 참조 기반이며 특정 설치본 소스·DB·런타임 호환성 검증이 아니다.

- **관리자 기술 권고:** 공통 PHP/MySQL 계열 백엔드 하나에 독립 설치용과 그누보드용 연결부를 두는 안을 우선한다. 소재·편성·로그·통계와 화면 본문을 공유하고, 연결부는 로그인·권한·CSRF·DB 접속/접두사·파일 경로·메뉴·콘텐츠 식별을 담당한다. 별도 Node 서버 프로세스를 설치 조건으로 추가하지 않는 안이며 기술 선택은 아직 확정하지 않았다.
- **플러그인 경계:** 광고 편성·별도 데이터·관리자 통계가 필요하므로 plugin 관리 화면과 작은 extend 연결부가 적합하다. 기존 회원·게시글·첨부파일 테이블을 광고 저장소로 사용하지 않고 제품 전용 테이블과 업로드 경로를 둔다. 외부 URL 자산과 소유한 업로드 파일을 구분한다.
- **콘텐츠 식별:** 공통 콘텐츠/영상 ID를 그누보드의 게시판 ID와 글 번호, 글 안의 개별 영상 키에 연결하는 안이다. 글 하나의 여러 영상을 구분하고 DOM 순서나 만료 URL을 영구 ID로 쓰지 않는다. 영카트 지원에서 주문·결제 기능까지 범위를 넓히지 않는다.
- **설치 수명:** 설치/업데이트에서 스키마 버전을 관리하고 비활성화 시 데이터는 보존하는 안이다. 제거와 파일 삭제는 제품 소유 데이터만 대상으로 별도 정의한다. 지원 PHP/DB/그누보드 버전은 실제 검증 환경 선택 후 명시한다.
- **외부 URL/업로드 통합:** 두 입력은 소재 ID·버전·재생 URL·종류·표시 시간으로 정규화한다. 플레이어는 공통 실행 경로를 사용하고 파일 저장·검증은 관리자 측이 맡는다. 원격 파일의 서버 다운로드/변환/CDN 기능은 아직 요구하지 않았다.

근거: `/Users/brian/works/gnuboard/sirqa/gnuboard5-llmwiki/docs/g5guide/developers/플러그인만들기.md`, `docs/wiki/common-use-patterns.md`, `skills/g5-plugin-guide/references/database_schema.md`. 오케스트레이터가 해당 문서의 extend/plugin 구분과 게시판·글 식별 구조를 직접 대조했다. 실제 사이트 DB에 접근하거나 타 프로젝트에 파일을 작성하지 않았다.

탐색 세부 규칙에 대한 구현 담당의 권고와 리뷰는 다음과 같다.

| 쟁점 | 제안 | 리뷰 상태 |
| --- | --- | --- |
| 여러 미시청 구간 통과 | 출발 지점보다 뒤이고 도착 지점 이하인 구간 중 가장 이른 것 하나를 실행 | 시간순 편성을 유지하는 일관된 기본값 후보. 사용자 확정 전 |
| 나머지 구간 | 탐색 직후 연달아 실행하지 않으며, 나중에 뒤로 돌아가 다시 통과할 때 후보로 유지 | 한 구간만 실행한다는 요구와 일치. 세부 이력 정책으로 제안 |
| 뒤로 탐색 | 즉시 광고 없이 이동하고 다음 순방향 통과에서 미처리 구간 평가 | 권고 기본값 |
| 처리 이력과 시청 결과 | 실행 중복 방지용 상태와 완료·스킵·오류 로그를 분리 | 설계 방향 채택. 스킵·오류 후 재실행 여부는 추가 결정 |
| 반복 탐색 이벤트 | 한 탐색 동작의 최종 위치로 한 번 판단하고 활성 구간 중복 시작 차단 | 구현 인수 조건에 포함 |
| 다시보기/재연결 | URL 변경만으로 이력을 초기화하지 않고 콘텐츠와 재생 세션을 명시적으로 식별 | 방향 채택. 같은 영상 다시보기 시 새 광고 세션 여부는 미정 |
| 끝으로 탐색 | 놓친 미드롤과 포스트롤이 연이어 실행되는 안 | 자동 채택하지 않음. 한 구간 보충 정책과 종료 UX의 우선순위를 별도 결정 |
| 동일 시각 구간 | 하나의 구간 안에서 광고 순서를 편집하고 중복 구간 ID는 거부 | 편집 검증 기본값 후보 |

권고 예시: 10·20·30초 구간이 있을 때 0→35초 탐색은 10초 구간 하나만 실행하고 35초 본편으로 복귀한다. 20·30초 구간을 곧바로 이어 실행하지 않는다. 이 예시는 선택 규칙 채택 후 인수 조건으로 확정한다.

### 공통 계약 작업에서 정할 세부 기본값

사용자는 D10–D12 제안을 그대로 채택하고 Herdr 실행 조직 구성을 지시했다. 큰 제품 범위는 다시 질문하지 않으며 아래 세부값을 담당자가 제안하고 오케스트레이터가 검토한다. 사용자가 결정한 사실과 기술적으로 선택한 기본값을 구분해 기록한다.

1. 계층별 편성 전체 대체/상속/광고 비활성화, 콘텐츠 전환·다시보기의 재생 세션 경계.
2. 미시청 구간 선택, 스킵·오류 후 중복 방지, 이미지 시간·탭 숨김, 음량·일시정지·클릭·접근성.
3. 광고 요청/소재 로드/재생 실패 처리와 시간 제한.
4. 서버 기술·지원 환경·배포 형식·브라우저/재생 엔진 호환 범위.
5. 관리자 권한, 통계 분모·중복 제거·보존 설정, 자동/실제 브라우저 인수 조건.

범위를 넓히는 캠페인 자동 선택·방문 간 빈도 제한·과금·정산·라이브·VAST/IMA·React는 현재 작업에 추가하지 않는다.

## 진행 순서

1. 분석 담당자의 근거를 오케스트레이터가 실제 코드와 대조한다.
2. 딥인터뷰 답변을 D01 이후 결정 항목으로 기록하고 첫 출시/후속/제외 범위를 확정한다.
3. 구현 담당자의 제안을 검토해 패키지 경계, 공개 API, 수명 관리, 테스트와 예제 위치를 결정한다.
4. 완료 조건을 포함한 작은 작업 단위를 구현 담당자에게 순서대로 배정한다.
5. 변경별 소스·타입·테스트 검증 후 실제 브라우저에서 광고 시작/스킵/종료/실패/콘텐츠 복귀를 확인한다.
6. 최종 리뷰에서 테스트 통과, 브라우저 동작, 광고 서버 연동, 배포 여부를 각각 보고한다.

## 후보 구현 단위와 인수 시나리오

아래는 범위 확정 전 검토안이다. 특정 광고 공급자·배포 형식·브라우저 지원을 확정한 목록이 아니다.

| 단계 | 산출물 후보 | 선행 결정 | 핵심 인수 시나리오 |
| --- | --- | --- | --- |
| P0 계약 | 편성 JSON·이벤트 계약, 논리/물리 데이터 구조, 관리자 화면과 HTML VOD 지원 표 | D01–D12와 후속 정책 | 같은 게시 편성·소재 버전을 관리자/플레이어/로그에서 식별할 수 있음 |
| P1 모듈 기반·편성 | 선택형 광고 패키지, 플랫폼 중립 스케줄러, 실행 상태·JSON 검증 | 배포·seek·재시청 정책 | 프리롤 1개/여러 개·미드롤·포스트롤 순서가 맞고 같은 구간이 중복 실행되지 않음 |
| P2 소재 실행·본편 연동 | MP4/WebM·이미지/GIF 렌더러, 스킵, 제어권·취소·시간 제한·복귀 | 시간·실패·컨트롤 정책 | 혼합 광고 묶음, N초 경계, 실패 복귀, 포스트롤 후 종료 유지, 늦은 응답 폐기 |
| P3 관리 저장·소재 화면 | 선택한 설치 환경의 접근 제어·소재/편성 저장과 관리 API, 소재 등록·미리보기·교체 | D07·D09, 저장/접근 정책 | 등록 후 새로고침해도 데이터 유지, 잘못된 소재 거부, 권한 범위 밖 수정 차단 |
| P4 편성 관리자·게시 | 대상/구간/순서/스킵 편집, 검증, 플레이어 미리보기, 게시 JSON | 적용 대상·버전 정책 | 저장·게시한 편성과 실제 실행이 같고 진행 중 세션은 정해진 버전 정책을 따름 |
| P5 로그·통계 | 이벤트 생성·수집·저장·중복 제거·집계, 통계 화면 | 이벤트 의미·보존·수신 계약 | 중복/역순 이벤트로 수치가 부풀지 않고 미재생·실패를 완료로 집계하지 않음 |
| P6 배포·통합 인수 | HTML 스크립트 설치 예제, 빌드·호환 확인, 자동/브라우저 검증 | 지원 조합·패키지 공개 범위 | 실제 관리자 등록→게시→플레이어 광고→수집 로그→통계를 하나의 흐름으로 검증 |

P1–P2는 P0의 fixture로 진행 가능하며 관리자 UI 완성에 종속되지 않는다. P3–P5의 파일 경로와 담당은 서버 기술·호스트 연결 구조 결정 후 배정한다. 제품 코드 구현 전에 각 단계의 수정 허용 파일과 인수 조건을 구현 담당자에게 명시한다.

공통 확인 대상: 정상 시작/종료, 혼합 소재 연속 광고, 스킵 경계, seek로 여러 구간 통과·역방향 탐색, 포스트롤/다시보기 경합, 광고 없음, 목록 요청 지연/실패, 미디어 오류/재생 거절, 중복 play, 콘텐츠/광고 URL 변경, 연결 해제/재연결, 다중 플레이어, 본편 볼륨·시간 복귀. 관리자 저장·게시·소재 교체·통계 필터와 중복/역순/누락 로그도 포함한다. 실제 출시 지원 대상으로 선택한 브라우저·엔진·전체 화면·PiP·Cast 조합은 별도로 검증한다.

현재 `PlayerExtensionCoordinator`는 같은 미디어에서 컨테이너만 바뀌면 확장을 다시 attach하지 않으며, 미디어 override는 먼저 등록된 확장이 우선한다. 광고 UI의 컨테이너 이동과 다른 확장과의 제어권 충돌을 구현 전 검증 항목으로 남긴다. 내부 확장 등록 API를 공개 플러그인 API로 승격할지, 저장소 내부 바인딩으로 사용할지도 미결정이다.

## 검증 상태

- 기존/현재 광고 관련 소스와 문서 일부 직접 확인: 수행.
- Herdr 에이전트 생성 및 실제 작업 상태 확인: 수행.
- Herdr 5개 담당의 W0 배정·응답·오케스트레이터 리뷰와 구성 재검토: 수행. 다음 작업 C0는 착수 가능 상태이며 제품 코드 구현 완료를 의미하지 않음.
- 두 에이전트의 분석 보고 수신 및 주요 소스 근거 대조: 수행.
- 제품 범위: 목적·자체 JSON·HTML/스크립트·VOD, 관리자 UI·데이터/로그 구조, 프리롤/미드롤/포스트롤·연속 광고, 영상/이미지/GIF·광고별 스킵, 독립 설치/그누보드 연동, URL/업로드 등록, 탐색 후 미시청 한 구간 실행 확정. 서버 기술·세부 편성/UX·배포·통계 정의는 미완료.
- 3차 에이전트 분석과 오케스트레이터 검토: 수행. 데이터/실행 모델은 설계 제안이며 API·스키마를 구현한 상태가 아님.
- 4차 에이전트 분석과 오케스트레이터 검토: 수행. 설치형/그누보드 연동 구조와 탐색 세부 규칙은 권고안이며 서버 기술·제품 기본값은 아직 확정하지 않음.
- 광고 코드 이식 또는 신규 구현: 수행하지 않음.
- 광고 단위 테스트, 브라우저 광고 재생, 서버 트래킹 수신: 수행하지 않음.
- 기존 Sandbox 서버 실행·본편 재생 확인은 광고 동작 검증으로 간주하지 않는다.

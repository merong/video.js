# L 강의(LMS) 화면 디자인 인계

강의 프리셋(`lms`)에 새로 들어가는 화면 요소의 값이다. 플레이어 안 요소, 플레이어 밖 패널 `<solad-lms-panel>`, 관리자 화면, 데모 `lecture.html`, 문구표를 다룬다.

- 작성: 2026-10-22, ads-admin-designer (L-1-DESIGN)
- 근거 명세: `.agents/plans/ads-lms-spec.md`(이하 "명세 2.6"처럼 절 번호), 코드 사실 `.agents/plans/ads-lms-facts.md`
- 형식 본보기: `.agents/plans/ads-player-design-handoff.md`
- 시안:
  - 정적 HTML `workspaces/ads-lms-20261022/design/lms-mock.html`과 `lms-mock.css`. file://로 연다.
  - 화면 사진 `shot-*.png`:
    - `w1280`, `w768`, `w390`, `w390d`, `w390r`
    - `states`(패널 상태 9개)
    - `w1280-forced`(강제 색 흉내)
    - `slider-zoom`(시간 슬라이더 확대)
  - 시안 CSS의 클래스(`.pl-*`, `.lms-*`)는 그림용이다. 실제 이름은 이 문서의 표를 따른다.
- 값의 출처 표시:
  - **명세**: 명세에 있는 값이다.
  - **시안**: 시안에서 정하고 사진으로 확인한 값이다.
  - **제안**: 명세에 없거나 명세와 다르게 권하는 값이다. 6절에 모았다.
- 색:
  - 플레이어와 패널은 관리자 토큰(`design/tokens.css`)과 관리자 CSS를 불러오지 않는다(명세 2.6).
  - 색 이름은 기본 스킨 변수(`--media-primary`, `--media-accent-color`)와 새 변수(`--solad-lms-*`)로 적는다.
- 폭 기준:
  - "로더 root 폭"이 기준이다.
  - 390은 페이지 390에서 양옆 16px을 뺀 358이다.
  - 768은 736–768, 1280은 1248–1280으로 본다.
- 시각 표기:
  - 명세의 `mm:ss`는 자리표시다.
  - 실제 표기는 기본 스킨 시간 표시와 같은 `m:ss`이고, 1시간 이상이면 `h:mm:ss`다. 예: `0:34`, `12:05`, `1:02:09`.

### 1.5 시간 슬라이더: 시청 구간 층과 한계 표시

#### 층의 구분

| 층(아래 → 위) | 색 | 두께 | 출처 |
| --- | --- | --- | --- |
| 트랙 바탕 | `currentColor` 20% | 트랙 높이(`--media-spacing` = 4px) | 기본 스킨 |
| 버퍼 | `currentColor` 20%(바탕 위에 겹쳐 약 36%) | 같음 | 기본 스킨 |
| **시청 구간** | `color-mix(in oklab, var(--media-primary) 65%, transparent)` | 트랙과 같은 높이, 같은 둥근 끝 | **시안** |
| 채움(재생 위치까지) | `--media-primary` | 같음 | 기본 스킨 |
| 장 사이 틈 | 기본 스킨의 장 분할 그대로. 시청 층도 장마다 잘린다 | — | 기본 스킨 |
| **한계 표시** | 세로 막대 2×12px, 반지름 1px. 색 `--solad-lms-limit-color`(기본 `#fff`), 바깥 `0 0 0 1px #00000080` | 트랙 위아래로 4px씩 나온다 | **시안** |
| 썸 | 기본 스킨 그대로. 한계 표시보다 위 | — | 기본 스킨 |

- 시청 구간은 버퍼보다 진하고 채움보다 옅다. 기본(흰색 강조)에서도 바탕·버퍼·시청·채움이 20 → 36 → 65 → 100% 순으로 구분된다(사진 `slider-zoom`).
  - 처음에 55%로 그렸더니 버퍼와 너무 가까워서 65%로 올렸다.
- 재생 위치보다 앞의 시청 틈은 채움에 덮여 보이지 않는다. 장별로 얼마나 봤는지는 패널 목차의 작은 막대가 보여 준다(2.5).
- 한계 표시는 `seekLimit: watched`이고 아직 완료하지 않았을 때만 그린다. 완료하면 바로 지운다.
- 모든 층과 표시는 `pointer-events: none`이다(명세 2.6).
- 미리보기(썸네일과 장 제목)는 그대로 둔다. 한계 뒤를 가리켜도 미리보기는 보인다.
  - 누르면 1.3 막힘 알림이 뜨고 한계로 간다.

#### 변수 이름(제안)

| 변수 | 다는 곳 | 값 | 쓰는 쪽 |
| --- | --- | --- | --- |
| `--solad-lms-watched` | `media-time-slider` host | `linear-gradient(to right, …)`. 전체 길이 기준 %로 구간마다 `var(--solad-lms-watched-color) a% b%`, 나머지는 `transparent` | lms.js가 구간이 바뀔 때 쓴다(초당 1번 이하) |
| `--solad-lms-watched-color` | 스킨 CSS 기본값 | `color-mix(in oklab, var(--media-primary) 65%, transparent)` | 스킨 |
| `--solad-lms-limit` | `media-time-slider` host | 한계 위치 %(`35.2%`). 없으면 표시를 숨긴다 | lms.js |
| `--solad-lms-limit-color` | 스킨 CSS 기본값 | `#fff` | 스킨 |

#### 넣는 자리(스파이크 7-6과 함께 정함)

- **시청 층**: `div.solad-lms-watched`를 장 `<template>` 안 track의 fill **앞**에 넣는다.
  - 장마다 복제되므로, 층을 슬라이더 전체 좌표로 늘리고 장 밖은 잘라 낸다.
  - 장 변수 `--media-slider-chapter-start/width`를 써서 `left: -(start ÷ width) × 100%`, `width: (100 ÷ width) × 100%`로 둔다. track은 `overflow: clip`이다.
  - 변수 단위(% 숫자인지 길이인지)는 스파이크에서 확인한다.
  - 이 방법이 안 되면 대안이 있다:
    - `media-time-slider`의 직접 자식으로 트랙 자리에 층 하나를 둔다.
    - 그 층은 트랙들 **위**에 칠한다. 65% 강조색을 100% 강조색 위에 칠하면 같은 색이라서, 채움 위에 덮여도 모양이 같다.
    - 장 틈은 lms.js가 장 시각으로 만든 `mask-image`로 뚫는다.
    - 시안은 이 방식으로 그렸다.
- **한계 표시**: `i.solad-lms-limit`를 `media-time-slider`의 직접 자식으로 둔다(chapters 안은 지워진다, 사실표 60행). `left: var(--solad-lms-limit)`, 세로 가운데.

## 2. 플레이어 밖 패널 `<solad-lms-panel>`

### 2.1 배치

로더 root 안에 감싸개(`.solad-lms`, `container: solad-lms / inline-size`)를 두고 그 안에서 플레이어와 패널을 grid로 놓는다.

| root 폭 | 배치 | 패널 크기 | 스크롤 | 출처 |
| --- | --- | --- | --- | --- |
| ≥ 960px | 옆. `grid-template-columns: minmax(0, 2fr) minmax(0, 1fr)`, 간격 16px | 높이는 플레이어와 같다(`contain: size` + grid 늘이기). 1280에서 플레이어 843×474, 패널 421×474 | 탭 아래 몸통만 스크롤 | 명세, 사진 `w1280` |
| < 960px | 아래. 한 줄, 간격 12px | 폭은 플레이어와 같다. 최대 높이 **384px** | 같음 | 명세(24rem), 값은 **제안**(6절). 사진 `w768`, `w390` |
| 768 | 아래 | 768×384 | 같음 | 사진 `w768` |
| 390(358) | 아래 | 358×384 | 같음 | 사진 `w390` |

- 머리와 탭 줄은 고정이고 몸통(`.solad-lms-body`)만 `overflow: auto; overscroll-behavior: contain`이다.
- 가로 스크롤은 없다. 시안 측정에서 패널과 플레이어 밖으로 나간 요소는 0개였다.
- 탭이 모두 꺼지면 패널 대신 머리만 있는 진도 줄을 그린다. 이때 높이는 머리 높이다(명세 1.1).
- 내장 전체화면에서는 패널이 보이지 않는다(명세 2.6).

### 2.2 바탕·색·글꼴

- 패널은 **자기 바탕을 가진다**.
  - 고객 페이지가 밝든 어둡든 읽혀야 하고, 페이지 바탕을 알 수 없어서다.
  - shadow DOM에 그려 페이지 CSS가 들어오지 않게 하는 것을 권한다(**제안**).
- 밝기 체계: 기본 `color-scheme: light dark`로 OS 설정을 따른다.
  - 고객 페이지가 `solad-lms-panel { color-scheme: dark }`(또는 `light`)로 고정할 수 있다. 이 방법을 도움말에 적는다.
- 글꼴: `var(--media-font-family, "Inter Variable", Inter, ui-sans-serif, system-ui, sans-serif)`, 14px/1.5.
- 강조색: `var(--media-accent-color)`.
  - 로더는 지금 프리셋 CSS 변수를 스킨 요소에만 단다(`applyPresetCss(skin, …)`).
  - 패널에도 같은 변수를 달아야 한다(**제안**, 구현 메모).

| 변수 | 밝게 | 어둡게 | 쓰임 |
| --- | --- | --- | --- |
| `--solad-lms-surface` | `#ffffff` | `#18181b` | 패널 바탕 |
| `--solad-lms-surface-2` | `#f4f4f5` | `#232327` | 현재 행, 버튼, 막대 바탕 |
| `--solad-lms-text` | `#18181a` | `#f4f4f5` | 글, 기본 버튼 바탕, 초점 고리 |
| `--solad-lms-sub` | `#5f5f66` | `#a1a1aa` | 보조 글, 시각 |
| `--solad-lms-line` | `#e4e4e7` | `#34343a` | 구분선, 테두리 |
| `--solad-lms-accent` | `var(--media-accent-color, var(--solad-lms-text))` | 같음 | 진도 막대, 현재 탭 밑줄, 현재 행 왼쪽 막대, 검색 표시 |
| `--solad-lms-warn` | `#8a5300` | `#f5b14c` | 저장 경고, 자료 일부 실패 |
| `--solad-lms-bad` | `#b42318` | `#ff8a80` | 저장 실패, 지우기 버튼 |
| `--solad-lms-radius` | `12px` | — | 패널 모서리 |

- 값은 `light-dark()`로 쓴다.
- 강조색은 뜻을 혼자 지지 않는다.
  - 진도 막대에는 안쪽 테두리(`text` 35%)를 둔다.
  - 현재 행은 강조 막대에 굵은 글과 바탕을 더한다.
  - 현재 탭은 강조 밑줄에 굵은 글과 진한 글색을 더한다.
  - 그래서 흰색이나 라임(#CDF352)처럼 밝은 강조색을 밝은 바탕에 써도 상태가 보인다(사진 `w390`).
- 기본(채운) 버튼은 강조색이 아니라 `text` 바탕 + `surface` 글자다. 강조색이 무엇이든 대비가 보장된다.
- `prefers-contrast: more`: `sub` = `text`, `line` = `text` 60%.
- `forced-colors`: 진도 막대, 현재 행 막대, 현재 탭 밑줄은 `Highlight`. 검색 표시는 `Mark`. 사진 `w1280-forced`에서 확인했다.

### 2.10 키보드와 스크린 리더

- 패널 이름: `<section aria-label="강의 진도와 자료">`(landmark `region`).
- Tab 순서:
  1. 탭 줄(Tab 한 번)
  2. 몸통의 도구 줄(검색칸, 버튼, 스위치)
  3. 목록(Tab 한 번, roving)
  4. 파일 링크
  5. 아래 안내 줄(누를 것 없음)
- 머리에는 누를 것이 없다.
- 플레이어 → 패널 순서는 DOM 순서와 같다. 옆 배치에서도 플레이어가 먼저다.
- 초점 고리: `outline: 2px solid var(--solad-lms-ring)`(= text), `outline-offset: 2px`. 탭은 `-4px`.
- 플레이어 단축키가 패널 입력칸(검색, 메모)에서 먹지 않아야 한다. `b`, `j`, `k`, `l`, 숫자, Space를 L-3에서 확인한다(미확인).
- 패널에서 이동을 누르면 초점은 패널에 남는다. 영상으로 옮기지 않는다.
- 패널 메시지는 1.9의 live 하나로 읽는다.

## 6. 명세와 다르게(또는 더해) 제안한 것

1. **패널 아래 배치 최대 높이 24rem → 384px**(명세 2.6).
   - 패널은 고객 페이지에 들어간다. rem은 고객 페이지의 root 글자 크기를 따르므로, 62.5% 같은 설정이 있으면 240px로 줄어든다.
   - 기본 16px에서는 같은 값이다.
2. **패널도 프리셋 CSS 변수를 받아야 한다**(명세 2.6 "패널이 `--media-accent-color`를 따른다"를 지키기 위한 구현 조건).
   - 로더가 지금은 스킨 요소에만 변수를 단다.
   - 패널 요소(또는 둘을 감싼 `.solad-lms`)에도 같은 변수를 달아야 한다.
3. **aria-live를 플레이어 안 하나로 모은다**(명세 2.6 "알림은 한 곳에서").
   - 패널 메시지도 같은 live를 쓰고, 패널은 live를 따로 두지 않는다.
   - 패널이 없는 경우(탭 넷 끔)에도 동작하고, 두 곳이 겹쳐 읽는 일이 없다.
4. **알림이 떠 있는 동안 제목을 숨긴다**(명세에 없음).
   - 위 가운데 알림이 제목 줄과 겹쳐 보였다(시안 첫 사진).
   - 아래쪽은 자막과 컨트롤이 있어 피했다.
5. **이어보기 버튼 순서**: 보이는 순서는 "처음부터" | "이어서 보기"이다.
   - 명세는 "이어서 보기"(기본 초점), "처음부터" 순으로 적었다. 초점은 명세대로 "이어서 보기"다.
   - 주 동작을 오른쪽 끝에 두는 플레이어 대화상자 관례를 따랐다.
   - 명세 순서를 지켜야 하면 순서만 바꾸면 된다.
6. **이어보기 오버레이가 프리롤보다 먼저다**(명세에 없음). 광고 뒤에 물으면 학습자가 광고를 본 뒤 다시 처음부터를 고를 수 있어 어색하다.
7. **매니페스트 전체 실패 문구**: "강의 자료를 읽지 못했어요".
   - 명세는 "같은 안내"("강의 자료 중 n개를 읽지 못했어요")다.
   - 전체 실패에서는 n을 알 수 없거나 의미가 없다.
8. **더한 상태**(명세에 없음):
   - 불러오는 중
   - 서버 저장 2번 연속 실패 경고
   - 학습자 토큰 틀림·만료 안내
   - 광고 중 패널 이동 막힘
   - 메모 한도 알림
   - 완료 알림 문구
   - 슬라이드 이미지 실패
9. **잠긴 장을 눌렀을 때**: 아무 일 없음 대신 한계로 이동하고 막힘 알림을 띄운다. 명세 2.4의 "목차 클릭도 한계에서 멈춘다"를 눈에 보이게 한 것이다.
10. **목차·스크립트 목록 roving tabindex**(명세에 없음). 문장이 수백 개면 Tab으로 빠져나갈 수 없다.
11. **"강의" 메뉴 자리**: 두 호스트 모두 "플레이어" 바로 뒤다. 명세는 handoff가 정한다고 했다.

## 7. 남은 질문

1. 메모 탭을 끄고 북마크 버튼은 켠 경우 북마크가 어디에 보이는지.
   - 지금 제안은 "저장은 되고 목록은 없음"이다.
   - 대안은 "메모 탭이 꺼지면 북마크 버튼도 숨김"이다. 편집기 도움말 문구가 이 결정에 달려 있다.
2. 시청 층을 장 template 안에 넣을 수 있는지. 스파이크 7-6이 정한다. 안 되면 1.5의 대안(슬라이더 직접 자식 + mask)을 쓴다.
3. seek indicator 처리(스파이크 7-7). 막힌 seek에서 indicator와 막힘 알림이 함께 뜨면 위 가운데가 겹칠 수 있다. 함께 뜨면 indicator를 빼는 쪽을 권한다.
4. 플레이어 단축키가 패널 입력칸에서 먹는지. 단축키 범위가 문서 전체면 패널에서 막아야 한다. 코드를 확인하지 않았다.
5. 그누보드 테마의 어두운 페이지에서 패널을 어둡게 고정할지. 기본은 OS를 따른다. 그누보드 스킨용 기본값이 따로 필요한지는 실제 테마로 봐야 한다.

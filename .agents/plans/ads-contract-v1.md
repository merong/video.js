# Ads v1 implementation contract (C0)

Owner: orchestrator. Date: 2026-10-18. This is the common implementation contract for the authorized D01–D12 scope, not a request for another user approval. Concrete defaults below are engineering decisions. Report contradictions before changing them; do not create incompatible DTOs in separate workstreams.

## Deliverables and ownership

- Player: `packages/extensions/ads/**`, package `@videojs/ads`, optional HTML/ESM script installation, current Video.js 10.1.0 integration. Keep runtime-neutral parser/scheduler separate from DOM. No React, live, VAST, IMA, campaign auction or paid billing.
- Manager API: `integrations/ads-manager/{src,database,public/api,hosts,bin,tests/backend}/**`, plus `public/index.php`, `public/router.php`, `.gitignore`, installation config example and README. PHP 8.2+ syntax, PDO MySQL production storage; PDO SQLite is supported for isolated local installation/tests. Do not connect to unrelated databases. No framework is required. Explicit migrations, never DDL during normal page GET.
- Manager UI: `integrations/ads-manager/admin/**`, `public/assets/admin/**`, `tests/admin/**`. Server-rendered shared PHP entry with progressively enhanced JavaScript/CSS; use host/API bootstrap, not a separate authentication or database layer.
- Root owns shared contract fixtures under `integrations/ads-manager/contract/**`, root pnpm/TS references, cross-package integration, demo fixtures and final docs. Analysts/QA do not modify product source.
- Native MP4 and existing HLS custom media are target content paths; advertising creatives are ordinary MP4/WebM or image URLs. Advertising media must not be discovered as the player's content media (use a shadow DOM overlay or equivalent isolation).

Browser integration surface: the ESM browser bundle exports `createAdsController({media,container,schedule,preview?,tracking?,onEvent?})` returning an object with `destroy()`. `media` is an explicit native/custom media target supporting playback/time/volume/events; `container` holds the ad overlay; `schedule` is the resolved DTO. `preview:true` suppresses network tracking but still invokes local onEvent when supplied. `tracking` is `{playbackSessionId,eventToken,expiresAt,eventsUrl}` from the manager response. The controller binds and waits for content play rather than autoplaying immediately. Controller teardown releases listeners/UI and invalidates pending asynchronous work. Other internal methods need not be public. The browser bundle also registers `<media-ads>` for HTML/script installs; the element accepts an explicit content media ID with `for`, a schedule/API URL with `src`, and a logical content ID with `video-id`. In a Video.js player use the existing exported contexts to register the internal extension; do not deep-import private HTML base classes or turn the internal extension contract into a stable public API. Unsupported missing target shows no ad and never hijacks another video. Package-neutral exports stay separate from DOM entry points. HTML registration must be safe under duplicate loads. The exact bundle filename is `dist/cdn/ads.js`; manager bootstrap `playerModuleUrl` points to its served copy/URL.

The HTML element fetches and distinguishes raw schedule versus `{ok:true,data:{schedule,...tracking}}`; imperative callers pass them separately. An element retains in-memory session/scheduler history across detach/reconnect when video-id, src and target identity stay unchanged; teardown cancels active work without retaining DOM/timers. Changing video-id/src or replacing the content source begins a new session and invalidates old requests. Explicit new imperative session is `old.destroy(); createAdsController(newOptions)`. Same-controller content replay retains history. Native `loadstart`/`emptied` or equivalent source identity changes must cancel even when the media object is unchanged.

An initial queued `emptied` → `loadstart` sequence for the same source before metadata or genuine playback is part of initial attachment, not a new session: preserve its issued tracking and held play intent across schedule fetch and controller attachment. A second load sequence, metadata-completed reload or actual source replacement invalidates the session; the HTML owner resolves a fresh schedule/session. An imperative owner must recreate the controller with fresh resolved data; the invalidated controller does not reuse the old video's schedule under an untracked random session. Teardown attempts bounded final delivery of already observed terminal/cancel events without allowing any late media/UI mutation; delivery remains best effort.

Preview example: `const {createAdsController}=await import(bootstrap.playerModuleUrl); const controller=createAdsController({media:previewVideo,container:previewContainer,schedule:previewResponse.schedule,preview:true});` Destroy the previous controller before replacing preview content/schedule or closing the panel. UI supplies a content video URL input for the preview and never invents successful playback.

## Wire conventions

JSON UTF-8. `schemaVersion: 1` is a wire format version; `scheduleVersion` is a positive integer published revision. Unknown schema or invalid ads must fail open to content with an error observation, not hold playback. All IDs are nonempty stable strings up to 128 characters. All numbers must be finite. Runtime URLs permit HTTP(S), including same-origin absolute-path URLs beginning with one `/`, but not protocol-relative `//`, javascript/data URLs or control characters. A URL is a reference, never a server-side download request. Same-origin is the default deployment; do not add permissive CORS.

HTTP API lives at `public/api/index.php?action=ACTION`. GET is read-only; writes are POST. JSON response is `{ok:true,data:...}` or `{ok:false,error:{code,message,fields?:{field:message}}}`. Status: 400 invalid, 401 login required, 403 forbidden/CSRF, 404 absent, 409 revision conflict, 413 size, 422 validation, 429 limit, 500 generic server error. Do not leak stack traces or paths.

## Content and resolved playback schedule

```json
{
  "schemaVersion": 1,
  "siteId": "site-local",
  "videoId": "video-1",
  "boardId": "free",
  "categoryId": null,
  "scheduleId": "schedule-site",
  "scheduleVersion": 1,
  "breaks": [
    {"breakId":"pre-1","position":"pre","ads":[
      {"itemId":"item-1","adId":"creative-1","creativeId":"creative-1","creativeVersion":1,"kind":"image","url":"/media/ad.png","mime":"image/png","alt":"광고","clickUrl":null,"skipAfterSeconds":2,"displaySeconds":5}
    ]}
  ]
}
```

- `boardId`/`categoryId` are nullable. `breaks:[]` is the valid resolved result of disabled/no matching published ads. It never means inherit at runtime. `scheduleId` can be `none` and version 1 for an empty resolved result.
- Each break has unique `breakId`, `position:pre|mid|post`; mid requires `atSeconds > 0`, other positions omit it. At most one pre and one post; mid positions must be unique. Sort pre, ascending mid, post. Each nonempty break has a nonempty ordered `ads` array with unique item IDs across a schedule. Limit 100 breaks and 20 ads per break.
- `kind:video|image`; MP4/WebM use `video/mp4|video/webm`; images support `image/jpeg|image/png|image/webp|image/gif`. GIF is `kind:image` and uses explicit display time; no attempt to count GIF loops. `alt` is required as a string (may be empty for video). Click URL is nullable.
- `skipAfterSeconds:null` means no skip. Otherwise an integer 1–3600. For image require `0 < displaySeconds <= 3600` and skip < displaySeconds. Video does not carry displaySeconds; use actual media progress/ended, not a declared duration to fake completion. If skip >= actual video duration it simply never becomes available.
- Server preview returns the same resolved schedule DTO but never creates a production tracking session. Player plain static JSON receives exactly the object above; manager `schedule` API returns the envelope with `{schedule,playbackSessionId,eventToken,expiresAt,eventsUrl}`. Token/expiry are transport metadata, not fields copied into the schedule. eventsUrl follows the same URL validation.

## Execution and media defaults

- One content session has one frozen schedule; publication changes apply only to new sessions. Host supplies stable video ID, not expiring source URL or DOM order. Source identity change cancels all old work. Destroy invalidates pending fetch/play promises and removes timers/listeners/overlay; never resumes different content.
- Preroll starts on a genuine play request, not on load. Break ads play in array order. Skip affects current ad only; countdown resets for the next. Ad failure/timeout advances to the next ad; a failed break does not prevent content. Request/load timeout 5 seconds, stalled video timeout 10 seconds; configurable within bounded positive values. Never classify failure/timeout as complete.
- During ads, isolate ad controls from content seek/replay and preserve latest user play/pause intention. Inherit content mute/volume and keep user changes consistent when returning. Autoplay rejection displays an explicit ad play button; do not count start before playback. Bound failed load/play waiting and permit content after the failure policy.
- Video progress is actual media playback time. Image duration/skip elapsed starts only after load success and accumulates while document is visible and ad not paused. Image timer pause does not promise GIF animation pause. UI provides ad indicator, current ad count, timer, current-ad skip, accessible play/pause/mute and click target. Keyboard focus must not reach covered content controls; restore prior focus when appropriate.
- Forward seek `(previous, final]` chooses the earliest unprocessed midroll crossed, exactly one. Other missed breaks stay eligible only if crossed again later; do not backlog them immediately. Backward seek starts none. Duplicate seek/timeupdate events cannot start duplicate breaks. Natural progression uses chronological cues.
- Once a break starts it is consumed for that session even if skipped or failed; telemetry still distinguishes results. Cancel before break start leaves it eligible. Replay/reconnect of the same logical session does not reset history; explicit new session or new video ID does. Do not expose implicit URL-query reset behavior.
- At an actual ended state, postroll takes precedence over missed-midroll compensation for a seek to the end. Do not run both as compensation. Postroll completion leaves content ended. A replay request during active postroll is ignored until it finishes (UI remains advertising controls), then ordinary replay preserves the current session history.
- Midroll at/after known finite content duration is invalid and reported, not silently repositioned. Defer duration-dependent validation until metadata; no NaN/Infinity cues. Initial scope does not advertise PiP/Cast ad support; unsupported remote/PiP transitions must not silently masquerade as verified ads. Native/fullscreen and supported target adapters require real tests before claiming compatibility.

## Administrator data and publication

Creative record: `{creativeId,version,name,kind,url,mime,alt,source:"url"|"upload",archived:boolean,createdAt}`. Immutable media versions; replacing creates a new version. Archive prevents new selection/publication but does not rewrite old snapshots or delete files used by sessions. No physical-delete UI in v1.

In v1 one creative record is one managed advertisement: `adId` equals `creativeId`. Media versions do not change adId. An item ID identifies a placement of that advertisement within a schedule. No separate ad CRUD endpoint or campaign entity is needed. Server publication canonicalizes this relationship.

Target: `{type:"site"|"board"|"category"|"video",id:string,boardId?:string}`. Site ID is configured locally. Category key is scoped to its board. Resolution priority: video > category within board > board > site. At each level mode is `inherit|replace|disabled`; site has replace/disabled only. First non-inherit published record wins, with entire schedule replacement and no array merge. Disabled stops fallback. No publication means inherit; all absent means no ads.

Editor record: `{target,mode,revision,breaks}`. Reuse runtime break/ad fields. Server validates creative ID/version against stored assets; do not trust a submitted URL override for a known creative. Save draft does not publish. `revision` is optimistic concurrency (new=0); save returns incremented revision. Publish uses expected draft revision, validates atomically and updates immutable scheduleVersion; old live version survives invalid publish/conflict. UI shows saved draft, unsaved edits, live version, resolved inheritance source and explicit disabled distinctly.

Host interface: `requireAdmin`, `verifyCsrf`, PDO connection/table prefix, upload root/public URL, `resolveVideoContext`, and admin bootstrap. Standalone admin login uses hashed passwords and session rotation; same-site HTTP-only session cookie (Secure when HTTPS). GnuBoard uses its existing super/menu admin authorization and admin token flow, not another password database. Configurable absolute GnuBoard root; fail closed when absent. No core file patch or use of unused member/post columns. GnuBoard video identity includes `bo_table + wr_id + stable video key`; honor host content access and category/board scope. A signed context or host-side resolution must not trust a visitor's arbitrary board query to bypass an explicit disabled video rule.

GnuBoard's default canonical identity is `bo_table:wr_id:main` for one content video per post. Validate the final key, not only post existence: an optional server-configured `gnuboardVideoKeys(board, post)` callback returns the host's allowed stable video keys for multiple videos. Unknown keys fail closed. This hook reads host-owned identity data; it never accepts a visitor's proposed mapping or derives permanent IDs from DOM order/source URLs.

Public upload default 100 MiB max configurable and constrained by PHP effective limits; fileinfo MIME allowlist, random generated storage name, dedicated non-executable directory. Never use client filenames as paths; reject symlinks/path traversal. URL creative validation is syntactic, preview verifies browser usability; do not fetch remote content from the PHP server. Do not infer file MIME from extension alone for uploads.

## Administrator API actions (v1)

- GET `bootstrap` -> `{authenticated,csrfToken,site:{siteId,timeZone},apiUrl,playerModuleUrl,limits:{uploadBytes},capabilities:{...}}`. Unauthenticated bootstrap returns authenticated false and login CSRF only, no protected data. Configured URLs are host-relative/absolute safe values. `playerModuleUrl` can be null until integration; UI marks preview unavailable rather than fake playback.
- POST `login` `{username,password}` + CSRF -> authenticated state; POST `logout` + CSRF. GnuBoard login redirects are host-owned, do not use standalone login endpoint there.
- GET `creatives` -> `{items:[Creative]}`; POST `creative-save` with URL input `{name,url,mime,alt,creativeId?:string}` (kind derived from MIME); POST multipart `creative-upload` with file/name/alt/optional creativeId; POST `creative-archive` `{creativeId}`.
- GET `targets` with type/query/optional boardId -> `{items:[{target,label}]}`. Standalone allows stable manual IDs; GnuBoard resolves verified choices. UI must distinguish manual vs host lookup capabilities.
- POST `video-context-save` (standalone admin only) `{videoId,label,boardId,categoryId}` registers a trusted video-to-board/category mapping for manual installation. UI may place this small form next to the video target selector. Unknown standalone video IDs use site/video rules with null board/category, ignoring visitor-supplied board/category; GnuBoard derives its context from host data. Stored video-level disabled/replace rules always override less-specific rules. GnuBoard never accepts this endpoint as a way to forge host membership.
- GET `schedule-draft` with targetType/targetId/boardId -> `{draft:{target,mode,revision,breaks},publishedVersion:null|integer,resolvedFrom:null|Target}`.
- POST `schedule-save` `{target,mode,revision,breaks}` -> same shape with updated revision; POST `schedule-publish` `{target,revision}` -> `{scheduleId,scheduleVersion}`.
- POST `schedule-preview` `{target,mode,revision,breaks,videoId,boardId,categoryId}` -> `{schedule}`. Require admin and validate assets; no production events/token.
- GET `stats` and `stats-csv`: filters `{from:YYYY-MM-DD,to:YYYY-MM-DD,adId?,videoId?,boardId?}`, inclusive site-local dates converted to UTC boundaries. Stats -> `{totals:{starts,completes,skips,clicks,clickedStarts,errors,completionRate,clickRate},rows:[{adId,videoId,boardId,starts,completes,skips,clicks,clickedStarts,errors,completionRate,clickRate}],timeZone,asOf}`. Rates 0..1 or null when starts=0. CSV same filters and grouping, Korean-safe UTF-8, escape cells and neutralize spreadsheet formula prefixes. Clicks are distinct accepted click events; clickRate uses distinct started attempts with >=1 accepted click.
- GET `schedule` with videoId plus host-validated context -> transport described above. Blank schedule allowed. POST `events` `{playbackSessionId,eventToken,events:[Event]}` -> `{accepted,duplicates,rejected}`. Max 50 events and bounded payload. Same origin only by default. Collector validates session/token, snapshot membership, IDs/types/finite times, duplicates and conflicting ID content. Never return a token in a URL or log it.

All admin reads require authorization except bootstrap's anonymous subset; all admin writes require auth + CSRF except login which still requires login CSRF. API error messages are user-safe and UI preserves input after save errors. Reasonable local request limits; avoid unbounded uploads/event bodies.

GnuBoard consumes its native admin token on each verified write. Administrator API responses refresh `X-CSRF-Token` when a new token is available, including validation failures after consumption; the UI adopts the header before handling success/errors. Keep native single-use verification. Do not automatically retry a mutation after an ambiguous network failure. Tokens remain in the admin session/header/body boundaries and never in URLs or public collector responses.

Shared UI response details: creative-save/creative-upload return `{creative:Creative}`; creative-archive and video-context-save return `{saved:true}`; login/logout return `{authenticated:boolean}`. Send CSRF as `X-CSRF-Token` header (or multipart `csrfToken` for upload). Bootstrap's full capabilities are `{host:"standalone"|"gnuboard",manualTargets:boolean,uploads:boolean,loginUrl:string|null}`; anonymous bootstrap also includes apiUrl and capabilities so UI can show the correct login path, but omits site/limits/creative data. Unknown schedule-draft returns revision 0, empty breaks and mode inherit (site defaults disabled). `public/index.php` is API-owned and sets `$adsPage = ['apiUrl' => <host-derived endpoint URL>]` before including UI-owned `admin/index.php`; no UI dependency on private service objects. UI obtains all remaining state via bootstrap. Statistics rows include only the exact documented metrics/keys; a missing rate is null, never NaN.

## Observed event and statistics contract

Event fields: `{schemaVersion:1,eventId,playbackSessionId,breakAttemptId,adAttemptId,breakId,itemId,adId,creativeId,creativeVersion,scheduleId,scheduleVersion,sequence,occurredAt,contentTimeSeconds,adElapsedSeconds,type,code?,stage?}`. `type:start|complete|skip|click|error|cancel`. Cancellation is operational, not a completed or started observation. sequence is positive per-ad-attempt; event ID remains unchanged on retry. IDs/correlation checked against the session snapshot. Server context supplies site/video/board/category, never trusts a caller override. UTC ISO timestamp is client observation; server records receivedAt independently.

- `start`: once actual video playback begins or image displays. `complete`: natural video ended or image's accumulated display duration only. `skip`: after the configured elapsed threshold. `error`: load/play/stall/invalid metadata timeout, with bounded code/stage. `cancel`: source/disconnect/user teardown. Exactly one terminal result per attempt; contradictory terminals must be recorded/rejected without double counting. Click only for an eligible started attempt; preserve bounded out-of-order data until start arrives.
- Keep unique `(site,eventId)` and attempt correlation constraints. Exact retry is duplicate; same ID/different content is conflict. Immutable raw facts plus derived aggregates; arrival order never creates inferred starts/completes. A terminal arriving before start can be retained and reconciled; no start means no completion numerator.
- Stats cohort is server receivedAt of the first valid start; site-local date filter, UTC storage. Completes/skips/clickedStarts count unique started attempts in that cohort. Errors with no start use error received date and are clearly errors, not starts. No terminal event is not auto-complete. Late valid events update aggregates. Preview sessions/events excluded.
- Browser delivery is best effort with bounded retry/queue, stable event IDs, no secrets in URLs; avoid fake guaranteed delivery claims. Server duplicate acceptance is idempotent. No visitor account/IP storage required for v1 viewer analytics. Operational retention configurable, default 90 days; no automatic deletion in initial feature path.

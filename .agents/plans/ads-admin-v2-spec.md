# 광고 관리자 v2 기획·명세

작성: ads-admin-designer, 2026-10-20. 근거: 사용자 딥인터뷰 7회차(아래 V01–V27)와 현재 구현(`integrations/ads-manager/**`, `.agents/plans/ads-contract-v1.md`) 검토.
상태: **기획 명세 초안**. 공통 API·DTO·DB 계약은 C0와 같은 방식으로 오케스트레이터가 C1에서 확정한다. 이 문서의 API 이름·필드는 그 입력이다.
적용 범위: **독립 설치판**의 전체 기능 명세다. 그누보드5 연동판은 1:1 문의 구조를 본뜬 광고 요청 기반의 간략판이며 `ads-admin-gnuboard-spec.md`를 따른다. 이 문서의 그누보드 관련 서술(§3 역할 매핑 등)은 그 문서가 우선한다.

## 1. 배경과 목표

v1 관리자는 **소재 → 대상(사이트·게시판·분류·영상)별 고정 편성 → 기본 통계**의 3화면 구조다. 편성 구간에 소재를 직접 배치하며 광고주·캠페인·기간·목표·선택 로직·역할이 없다.

v2 목표: 운영팀이 **기간제 판매, 노출 보장 판매, 하우스 광고**를 함께 운영한다. 광고주에게는 읽기 전용 성과 링크를 제공한다.

사용자가 꼽은 v1의 한계(V01): 실무 UX 부족, 리포트·대시보드 부족, 광고 선택 로직 부재.

## 3. 사용자와 권한

| 역할 | 할 수 있는 일 |
| --- | --- |
| 편집자 | 광고주·캠페인·집행·소재·지면 편성 작성과 수정, 승인 요청, 진행 중 집행 일시중지, 리포트 조회·CSV |
| 승인자 | 편집자의 모든 권한 + 소재 심사, 지면·집행 승인과 반려, 설치 설정 변경, 광고주 리포트 링크 발급·회수 |
| 광고주(링크) | 링크로 지정된 캠페인 하나의 성과를 읽기 전용으로 조회 |

- **독립 설치:** `admins`에 역할 컬럼을 추가한다. 기존 관리자는 이관 시 승인자가 된다. 설치 CLI에 역할 지정 옵션을 추가한다.
- **그누보드:** 메뉴 쓰기(w) 권한은 편집자, 최고관리자는 승인자로 매핑한다. 선택 설정 `gnuboardApprovers`(회원 ID 목록)로 추가 승인자를 지정할 수 있다. 읽기(r)만 있는 회원의 처리는 O4를 따른다.
- **자기 승인(V26):** 기본 허용. 승인 이력에 `selfApproved: true`로 표시한다. 설치 설정 `allowSelfApproval=false`이면 제출자와 다른 승인자만 승인할 수 있다.
- 권한 판정은 서버에서 한다. UI는 `bootstrap`의 `role`과 `capabilities`로 버튼을 숨기거나 비활성화할 뿐이다.

## 4. 도메인 모델

```
광고주 Advertiser
 └ 캠페인 Campaign            계약 단위. 계약 기간과 메모, 리포트 링크
     └ 집행 라인 LineItem      실제 노출 조건. 승인 대상
         · 등급: sponsorship(기간제) | guaranteed(보장) | house(하우스)
         · 기간, 요일·시간대, 콘텐츠 타겟, 슬롯 위치
         · 점유율 / 노출 목표 / 가중치, 스킵 정책
         └ 소재 연결 LineItemCreative  비중, 클릭 URL·이미지 표시 시간 재정의
              └ 소재 Creative (버전, 심사 상태)

지면 편성 Placement            사이트 → 게시판 → 분류 → 영상 상속(v1과 동일)
 └ 구간 Break (pre | mid@초 | post)
     └ 슬롯 수 1–20             무엇을 넣을지는 재생 시 선택
```

### 4.1 광고주와 캠페인

- 광고주: `{advertiserId, name, contactName?, contactEmail?, memo?, archived}`. 연락처는 운영 메모용이며 광고주 링크에는 노출하지 않는다.
- 캠페인: `{campaignId, advertiserId, name, startDate, endDate, memo?, archived}`. 계약 기간은 하위 집행 기간의 허용 범위다. 집행 기간이 이를 벗어나면 저장 시 검증 오류로 처리한다.
- 캠페인 상태는 하위 집행 상태로부터 계산한다(예정·진행·일시중지 포함·종료·보관).

### 4.2 집행 라인(LineItem)

| 필드 | 규칙 |
| --- | --- |
| `tier` | `sponsorship` / `guaranteed` / `house` |
| `startAt`, `endAt` | 사이트 시간대 기준 일시. 하우스는 기간 없이 상시 집행할 수 있다 |
| `sharePercent` | sponsorship 전용, 정수 1–100. 100은 해당 조건 슬롯의 독점 |
| `goalImpressions` | guaranteed 전용, 양의 정수 |
| `pacing` | v2는 `even` 고정(V07). 필드는 남겨 둔다 |
| `weight` | 같은 등급 내 비중, 정수 1–100, 기본 1 |
| `targeting.positions` | `pre`/`mid`/`post` 중 1개 이상 |
| `targeting.content` | 게시판·분류·영상별 include/exclude 목록. 비어 있으면 사이트 전체 |
| `targeting.dayparts` | `[{days:[1–7], from:"HH:MM", to:"HH:MM"}]`. 비어 있으면 항상. 자정을 넘는 구간은 두 항목으로 나눈다 |
| `skipAfterSeconds` | null(스킵 불가) 또는 정수 1–3600. v1 계약의 이미지 규칙(스킵 < 표시 시간)을 유지한다 |
| `creatives[]` | `{creativeId, weight 1–100, clickUrl?, displaySeconds?}`. 재정의가 없으면 소재 기본값을 쓴다 |

**상태 전이**

```
draft ──제출──▶ pending ──승인──▶ approved ─(기간·목표에 따라)─▶ scheduled / active / completed
  ▲              │반려(사유 필수)            │
  └──────────────┘                           ├─일시중지(즉시, 편집자 가능)─▶ paused ─재개(즉시)─▶ 이전 상태
                                             └─수정─▶ 새 draft 리비전(게시본은 계속 집행)
```

- 승인된 집행을 수정하면 v1 편성처럼 별도 초안 리비전이 생긴다. 승인 전까지는 기존 게시본이 계속 집행된다. `revision` 낙관적 동시성(409)은 v1과 같다.
- 재개는 이미 승인된 게시본을 되살리는 동작이므로 즉시 반영한다. 기본값이며 O9에서 확인한다.
- `completed`: 보장 집행이 목표에 도달했거나 종료 시각이 지난 상태. 목표 미달로 종료되면 "미달 종료"로 표시하고 자동 연장하지 않는다(O7).
- 보관(archive): 새 선택에서 제외한다. 과거 스냅샷과 통계는 보존한다.

### 4.3 소재(Creative)

v1 필드를 유지한다: 불변 버전, URL/업로드, MIME, 대체텍스트, 보관. 다음 필드를 추가한다.

- `defaultClickUrl`, `defaultDisplaySeconds`(이미지 전용).
- 심사 상태 `review: pending | approved | rejected`, 반려 사유, 심사자, 심사 시각. **심사 상태는 버전마다** 따로 둔다. 새 버전은 `pending`으로 시작한다.
- 집행 선택은 `approved` 버전만 사용한다. 최신 버전이 심사 대기 중이면 마지막 승인 버전으로 계속 집행하고, 화면에 그 사실을 표시한다.
- 반려된 소재는 집행 연결에 남지만 선택되지 않는다. 승인 가능한 소재가 하나도 없는 집행은 "소재 없음" 경고 상태가 된다.

### 4.4 지면 편성(Placement)

- v1의 대상 계층, `inherit|replace|disabled` 모드, 초안·리비전·`scheduleVersion`을 그대로 쓴다.
- 구간의 `ads[]`는 `slots: 정수 1–20`으로 바뀐다. v1 구간 제약(pre·post 각 최대 1개, mid 시각 중복 금지, 최대 100구간)은 유지한다.
- 게시 흐름: 초안 저장 → **승인 요청** → 승인자가 승인하면 게시(새 `scheduleVersion`), 반려하면 초안으로 돌아간다. 편집자는 직접 게시하지 못한다.

## 5. 재생 시 광고 선택

선택은 공개 `schedule` 요청 시 서버에서 한 번 수행한다. 결과는 v1처럼 서명된 세션 스냅샷에 고정한다. 플레이어는 선택 로직을 알 필요가 없다.

### 5.1 후보 조건

슬롯마다 다음을 모두 만족하는 집행이 후보다.

1. 상태가 `approved`이고 일시중지·보관 상태가 아니다.
2. 현재 시각이 `[startAt, endAt)` 안이고 dayparts와 일치한다(사이트 시간대).
3. 구간 위치가 `positions`에 포함된다.
4. 서버가 해석한 콘텐츠 문맥(게시판·분류·영상)이 include에 맞고 exclude에 걸리지 않는다. 방문자가 보낸 문맥 값은 v1처럼 신뢰하지 않는다.
5. 승인된 소재 버전이 1개 이상 있다.
6. 보장 집행은 페이싱상 노출 여력이 있다(§5.3).

### 5.2 선택 순서

```
슬롯 1개마다:
1) 기간제: 0–99 난수 r을 뽑는다. 후보를 안정 정렬(승인 시각, ID)한 뒤 점유율을 누적하다가 r < 누적값이 되는 집행을 선택한다.
   점유율 합계가 100을 넘으면 비율로 정규화하고, 승인 단계에서 경고한다.
2) 미선택이면 보장: 페이싱 여력이 있는 후보 중 진도율(실제 노출 ÷ 현재까지 기대 노출)이 가장 낮은 집행을 고른다.
   진도율이 같으면 가중치 비율로 무작위 선택한다.
3) 미선택이면 하우스: 가중치 비율로 무작위 선택한다.
4) 그래도 없으면 빈 슬롯으로 기록하고 광고 없이 다음 슬롯으로 넘어간다.
선택된 집행 안에서는 소재 연결 가중치로 소재를 고른다.
```

- **세션 내 중복 방지(V08):** 한 구간 안에서 같은 집행이 두 번 선택되지 않는다. 한 세션 안에서는 같은 등급에 대안이 있으면 이미 쓴 소재를 피한다. 대안이 없으면 다시 선택하는 것을 허용한다. 엄격한 "세션당 1회" 제한은 두지 않는다. 슬롯이 비는 것을 막기 위한 기본값이다.
- 빈 슬롯은 플레이어 DTO에 포함하지 않는다. 광고가 0개인 구간은 DTO에서 제외한다. 서버 스냅샷에는 슬롯별 결과(`filled`/`unfilled`, 등급)를 남겨 채움률 통계에 쓴다.
- 테스트를 위해 난수원은 주입할 수 있게 한다. 선택 결과는 시드를 고정하면 재현할 수 있어야 한다.

### 5.3 기간 균등 페이싱

- 일 목표 = 남은 목표 ÷ 남은 일수(오늘 포함, 사이트 시간대). 매일 0시에 다시 계산한다. dayparts가 있으면 해당 요일·시간 구간만 일수와 시간 비율로 센다.
- 현재까지 기대 노출 = 일 목표 × 오늘 경과 비율. 오늘 확정 노출 + **보정 대기분**이 기대 노출 이상이면 그 집행은 이번 요청에서 제외한다.
- 보정 대기분 = 최근 발급했지만 아직 노출 이벤트가 오지 않은 선택 수 × 최근 노출 전환율. 이벤트 도착 지연으로 생기는 과노출을 줄이기 위한 값이다.
- 누적 확정 노출이 목표에 도달하면 즉시 후보에서 제외하고 `completed`로 둔다. 이미 발급된 세션에서 들어오는 노출은 계속 기록한다. 그래서 소폭 과노출이 생길 수 있다(O6).
- 기간 종료 시 미달분은 이월하지 않는다.

### 5.4 일시중지와 고정 스냅샷

일시중지는 **새로 발급하는 세션**에 즉시 반영된다. 이미 발급된 세션은 v1 원칙에 따라 스냅샷이 고정되어 있으므로 토큰 만료 전까지 해당 광고를 재생할 수 있다. 긴급 중지가 진행 중인 재생에도 반영되어야 하는지는 O1에서 결정한다.

## 6. 노출(impression) 정의와 플레이어 계약 변경

| 항목 | 내용 |
| --- | --- |
| 새 이벤트 | `type: "impression"`. 시도(attempt)당 최대 1회 |
| 발생 조건 | 영상: 실제 재생 진행 ≥ `videoSeconds`. 이미지: 로드 성공 후 누적 표시 ≥ `imageSeconds`. 광고가 기준보다 짧으면 자연 완료 시점에 impression을 먼저 보낸다 |
| 기준값 전달 | 스케줄 최상위 `impressionPolicy: {videoSeconds, imageSeconds}`. 설치 설정(기본 2/1, 각 0.1–30초)에서 오며 세션 스냅샷에 고정된다 |
| 서버 검증 | start 이후여야 한다. `adElapsedSeconds ≥ 기준` 또는 같은 시도에 complete가 있어야 한다. 중복·충돌·역순 규칙은 v1과 같다 |
| 버전 | 스케줄·이벤트 `schemaVersion: 2`. 플레이어는 1과 2를 모두 읽는다. v1 세션의 이벤트는 계속 받는다 |
| 플레이어 DTO 영향 | `impressionPolicy` 1개 필드와 이벤트 타입 1개만 추가한다. 집행·캠페인 ID는 서버 스냅샷이 `itemId`로 매핑하므로 플레이어에 보내지 않는다. `adId = creativeId`는 유지한다 |

보장 목표 차감, 진도, 광고주 리포트의 "노출"은 모두 이 impression 수다. 시작(start)은 보조 지표로 남는다.

## 7. 지표 정의

| 지표 | 정의 |
| --- | --- |
| 요청 슬롯 | 발급된 세션 스냅샷의 슬롯 수(채움 여부 무관). 서버 발급 기준이며 실제 재생 도달을 뜻하지 않는다 |
| 채움률 | 채워진 슬롯 ÷ 요청 슬롯 |
| 노출 | 유효 impression을 받은 시도 수 |
| 시작·완료·스킵·오류 | v1 정의 유지 |
| 완료율 | 완료 ÷ 시작(v1 유지) |
| 클릭률 | **v2 리포트: 클릭이 1회 이상 있는 노출 시도 ÷ 노출.** v1 통계 화면의 시작 기준 정의는 호환용으로 유지한다(O3) |
| 진도율 | 누적 노출 ÷ 목표(보장). 일 진도 = 오늘 노출 ÷ 일 목표 |

- 날짜·시간 버킷은 v1과 같다. 첫 유효 start의 서버 수신 시각을 사이트 시간대로 해석한다. 노출 카운트도 그 시도의 start 코호트를 따른다. 요청 슬롯은 발급 시각을 기준으로 한다.
- 기기 분류: `schedule` 요청의 User-Agent로 서버가 `pc|mobile|tablet|unknown`을 판정해 스냅샷에 둔다. 원문 UA와 IP는 저장하지 않는다.
- 집계 성능을 위해 시간 단위 롤업 테이블을 이벤트 수락 시 갱신하는 방안을 API 담당이 C1에서 제안한다. 원시 사실은 v1처럼 불변이다.

## 8. 화면 명세

### 8.1 정보 구조

```
[대시보드]*  [캠페인]  [소재]  [지면 편성]  [승인함 (n)]  [리포트]  [설정]
                                                   * 2단계
캠페인: 광고주 목록 · 캠페인 목록 → 캠페인 상세 → 집행 편집
```

공통 원칙:
- 목록에는 검색, 상태·기간 필터, 정렬, 페이지 이동을 둔다. 필터 상태는 URL 해시에 반영해 새로고침 후에도 유지한다.
- 호스트 조회가 가능하면 ID 직접 입력 대신 검색·선택을 쓴다. 독립 설치의 수동 ID 입력은 보조 경로로만 남긴다.
- 상태 배지 문구와 색을 통일한다(초안·승인 대기·예정·진행·일시중지·종료·미달 종료·반려·보관).
- 화면마다 빈 상태, 로딩, 오류, 409 충돌, 미저장 이탈 경고를 정의한다. 저장 실패 시 입력을 보존하는 v1 원칙을 유지한다.
- 접근성: 키보드 조작, `aria-live` 상태 알림, 대화상자 포커스 복귀를 지킨다. 모든 차트에는 같은 데이터의 표 대안을 둔다.
- 데스크톱 우선으로 설계하고 768px 폭까지 모든 기능을 쓸 수 있게 한다. 모바일 범위는 O5에서 정한다.

### 8.2 캠페인

- **광고주 목록:** 이름, 진행 캠페인 수, 최근 집행일. 생성·수정·보관.
- **캠페인 목록:** 광고주, 계약 기간, 상태, 집행 수, 보장 진도 요약(최저 진도 집행 기준). 필터: 광고주·상태·기간.
- **캠페인 상세:** 요약 카드(기간, 노출, 클릭률), 집행 라인 표(등급, 기간, 점유율/목표, **진도 막대와 일 진도**, 상태, 일시중지 버튼), 리포트 링크 관리(2단계), 승인 이력.
- **집행 편집(단계형 폼):** ① 기본(이름·등급) ② 기간·요일·시간대 ③ 등급별 조건(점유율 / 목표 / 가중치) ④ 타겟(위치, 콘텐츠 include/exclude 선택기) ⑤ 소재 연결(심사 상태 표시, 비중, 클릭 URL·표시 시간 재정의) ⑥ 스킵 정책 ⑦ 검토·제출.
  - 검토 단계 경고: 점유율 합계 100% 초과, 같은 조건에 독점 기간제가 있어 보장 목표 달성이 위험함, 승인된 소재 없음, 캠페인 기간 이탈, 해당 위치 슬롯이 있는 게시 지면이 없음.
  - 경고는 제출을 막지 않는다. 검증 오류는 제출을 막는다.
- **미리보기:** 집행을 특정 영상 문맥에 강제로 넣은 스케줄로 v1 미리보기 대화상자를 재사용한다. 통계에 기록하지 않는다.

### 8.3 소재

- 목록: 썸네일(이미지는 축소본, 영상은 첫 프레임 또는 아이콘), 이름, 형식, 최신 버전, 심사 상태, 사용 중인 집행 수. 필터: 심사 상태·형식·보관.
- 상세: 버전 이력(버전별 심사 상태·심사자), 기본 클릭 URL·표시 시간, 사용 중인 집행 목록, 미리보기.
- 업로드와 URL 등록은 v1과 같다. 저장하면 새 버전이 `pending`이 된다는 안내를 표시한다.

### 8.4 지면 편성

- 대상 선택: 사이트 / 게시판 / 분류 / 영상을 트리와 검색으로 고른다. 상속 출처와 현재 게시본 버전을 함께 표시한다.
- **타임라인 시각화:** 가로축은 본편 시간(미리보기용 길이 입력 또는 알려진 길이). pre, mid@초, post 마커와 슬롯 수를 블록으로 표시한다. 마커는 목록 편집과 동기화하며 키보드 대안을 둔다.
- 각 구간에는 "이 위치를 노릴 수 있는 진행 중 집행 수"를 보조 정보로 보여 준다. 슬롯을 늘려도 채울 집행이 없으면 하우스나 빈 슬롯이 된다는 것을 알리는 용도다.
- 하단 바: 미저장/초안/승인 대기/게시본 상태, `초안 저장`, `승인 요청`(편집자), `승인 후 게시`(승인자 바로가기).

### 8.5 승인함

- 탭: 소재 심사 / 지면 편성 / 집행. 각 탭에 대기 건수를 표시한다.
- 항목 상세는 **현재 게시본과 제출본의 차이**를 필드 단위로 보여 준다. 지면은 구간·슬롯 변경, 집행은 기간·목표·타겟·소재 변경이다.
- 동작: 승인, 반려(사유 필수). 자기 제출 건에는 "자기 승인" 표시를 하고, 금지 설정이면 버튼을 비활성화한다.
- 대상 화면에서도 승인 이력(제출자·승인자·시각·사유)을 볼 수 있다. 전체 감사 로그는 범위 밖이다.

### 8.6 리포트

- 필터: 기간(일), 광고주, 캠페인, 집행, 소재, 게시판, 영상, 위치, 기기.
- 행 기준: 1–2개 차원 선택(예: 캠페인 × 위치). 시간 단위: 합계 / 일 / 시(시간대별은 요일·시간 타겟 검증용).
- 출력: 상단 KPI(요청 슬롯·채움률·노출·완료율·클릭률·오류), Chart.js 추이 차트, 표, CSV(v1의 BOM과 수식 무력화 유지).
- v1 이벤트(이관 전)는 캠페인 차원에서 "미분류(v1)"로 묶는다.

### 8.7 대시보드(2단계)

- 오늘 요약: 노출, 완료율, 클릭률, 채움률, 오류 수. 어제 같은 시각과 비교한다.
- 추이: 최근 14일 노출·클릭 선 차트(Chart.js).
- 운영 할 일: 심사 대기 소재, 승인 대기 지면·집행, 7일 안에 종료되는 캠페인, 내 제출 중 반려된 건. 각 항목은 해당 화면으로 연결한다.
- 페이싱 경고는 대시보드에 두지 않는다(V14). 캠페인 목록과 상세의 진도 표시로 대응한다.

### 8.8 광고주 리포트 링크(2단계)

- 승인자가 캠페인마다 발급한다. 만료일은 기본 30일, 최대 180일이며 언제든 회수할 수 있다. 링크 여러 개를 허용하고 각각 이름(받는 사람)을 붙인다.
- 토큰은 128비트 이상 난수다. 서버에는 해시만 저장한다. 링크 목록에 마지막 접근 시각과 접근 수를 표시한다.
- 공개 범위(V27): 캠페인 KPI(노출·완료·클릭·완료율·클릭률), 일별 추이, 보장 집행별 목표 대비 진도, 같은 범위 CSV. 게시판·영상별 분해, 내부 ID, 다른 캠페인은 노출하지 않는다.
- 별도 공개 페이지로 제공한다. `noindex`, `Referrer-Policy: no-referrer`, 관리자 세션·CSRF와 분리하고 요청 수를 제한한다. 만료·회수된 링크는 동일한 안내 화면을 보여 존재 여부를 드러내지 않는다.

### 8.9 설정(승인자)

노출 인정 시간(영상·이미지), 자기 승인 허용, 링크 기본 만료일. 변경은 새 세션부터 적용하며 변경 이력을 남긴다.

## 11. 출시 단계와 인수 기준

### 1단계: 운영 기반

범위: 역할 2개, 광고주·캠페인·집행 CRUD, 소재 심사, 지면 슬롯화, 지면·집행 승인 흐름과 이력, §5 선택·페이싱, `impression` 이벤트(플레이어·서버), 설치 설정, v1 데이터 이관, 캠페인 상세의 진도 표시, v1 통계 화면에 캠페인·집행 필터 추가.

인수 기준:
- 편집자는 지면·집행을 게시하거나 승인할 수 없다. 서버 403을 테스트로 증명한다. 승인자 승인 후에만 새 게시본이 세션에 반영된다.
- 일시중지는 승인 없이 다음 발급 세션부터 제외된다.
- 고정 시드로 선택 순서(기간제 점유율 → 보장 진도 → 하우스 → 빈 슬롯)와 점유율 분포를 검증한다. 대량 반복에서 점유율 오차는 허용 범위 안이어야 한다.
- 페이싱 시뮬레이션: 균등 트래픽에서 일 노출이 일 목표 근처에 수렴하고, 목표 도달 후 신규 선택이 0이다.
- impression: 기준 미만 elapsed는 거부하고, 짧은 광고 완료 경로는 수락한다. 중복과 충돌은 v1 규칙대로 처리한다. 플레이어 단위 테스트와 실제 브라우저 관측은 별도 증거로 보고한다.
- 반려·대기 소재 버전은 선택되지 않는다. 승인된 이전 버전으로의 대체는 동작한다.
- 이관 후 v1 게시본과 새 구조의 노출 결과 비교 보고서(차이 목록 포함)를 만든다.

### 2단계: 가시성

범위: 대시보드, 다축 리포트·CSV·Chart.js 차트, 광고주 리포트 링크, 채움률·기기·시간대 지표.

인수 기준:
- 리포트 합계가 원시 사실 재계산과 일치한다(롤업 정합성 테스트).
- 광고주 링크는 다른 캠페인과 지면 분해에 접근할 수 없다. 만료·회수 후 접근이 거부된다. 토큰은 URL 쿼리와 로그에 남지 않는다.
- 모든 차트에 표 대안이 있고 키보드로 접근할 수 있다.

## 12. v1 데이터 이관(V28)

1. 기존 소재 버전은 심사 `approved`(이관 표시)로 둔다.
2. 각 게시 대상의 구간은 `slots = 기존 광고 수`로 바꾼다.
3. 구간에 배치됐던 소재마다 "이관 하우스 집행"을 만든다. 타겟은 해당 대상과 위치, 스킵·클릭·표시 시간은 기존 항목 값이며 승인 상태(이관)로 둔다. 이관용 광고주와 캠페인 "기존 편성 이관"을 하나 만든다.
4. 초안(미게시)은 슬롯 구조로 변환하되 집행은 만들지 않고 이관 보고서에 나열한다.
5. 과거 세션·이벤트는 변경하지 않는다.

알려진 동작 차이: 고정 순서가 가중치 무작위로 바뀐다. 같은 대상에 미드롤 구간이 여러 개면 위치(mid)가 같으므로 구간별 고정 소재가 섞일 수 있다. 이관 보고서에 이 차이를 대상별로 표시한다(O2).

## 13. 범위 밖

외부 광고 네트워크(VAST/IMA), 재고 예측, 방문 간 빈도 제한과 시청자 식별 저장, 기기·회원 등급 타겟팅, 광고주 계정과 셀프서비스, 과금·정산·청구서, 전체 감사 로그, 라이브, React, 자동 데이터 삭제.
